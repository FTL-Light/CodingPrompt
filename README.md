# CodingPrompt · AI 协作开发指南

一套面向 AI 辅助开发的流程手册，把「一句话需求」拆成可验收的六个阶段，适用于任何技术栈、任何 AI 编程工具（Claude Code、Cursor、Trae、Codex、Copilot、通义灵码等）。

核心思路：**规则先行、人是决策者、阶段有门禁**。每个阶段都有明确产出物和验收条件，上一阶段没通过，不进入下一阶段。

## 六阶段流程

```
需求探索 → 产品原型 → 项目设计 → 编码实现 → 测试验收 → 部署上线
         ↑ 发现需求问题可回退到上一阶段
```

| 阶段 | 目标 | 主要产出 | 验收门 |
|-|-|-|-|
| 1 需求探索 | 模糊想法 → 明确基线 | 需求文档 | 目标、角色、流程、边界、待确认项清楚 |
| 2 产品原型 | 需求 → 可点页面 | `prototype/` 可交互 HTML | 核心流程浏览器里能走通 |
| 3 项目设计 | 需求 → 可执行方案 | `docs/design/01~05` + SQL + 规范 | 模块/架构/库表/API 四者一致 |
| 4 编码实现 | 文档 → 业务代码 | 代码 + 单测 | 功能符合文档，核心流程跑通 |
| 5 测试验收 | 验证功能与安全 | 用例 + 测试报告 | 关键用例全过，无高危问题 |
| 6 部署上线 | 系统稳定运行 | Docker / CI / 手册 | 环境隔离、密钥、回滚就绪 |

## 怎么用

1. **项目启动**：先读 [00. 总览与协作规则](./00.总览与协作规则.md)，把「项目规则模板」复制为项目根目录的 `CLAUDE.md`（或 `AGENTS.md`、`.cursorrules`）。
2. **按阶段推进**：从 01 到 06 依次执行，每份文档都用「阶段定位 → 做法 → 提示词模板 → 验收清单」的结构组织。
3. **卡住就回退**：验收不通过时回到上一阶段补齐信息，而不是让 AI 在下游打补丁。
4. **控制范围**：一次只做一个功能，任务开始前先读文档，结束时汇报改动文件、验证方式与遗留问题。

## 沟通原则（摘要）

- 需求不清时先追问，不替用户做业务决定。
- 不确定的规则列为「待确认」，不擅自写进代码。
- 方案有多解时给出 2~3 种及取舍，由人拍板。
- 任务范围明确写死「做什么」和「不做什么」。
